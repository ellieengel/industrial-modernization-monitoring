# Системные требования

| ID | Требование | Приоритет |
|---|---|---|
| SR-01 | API импорта утверждённого проекта и плана | Must |
| SR-02 | Версионирование плана и защита утверждённой версии от изменения | Must |
| SR-03 | Внутренний UUID и mapping (source_code, external_project_id) | Must |
| SR-04 | Ежедневная синхронизация с настраиваемым временем и часовым поясом | Must |
| SR-05 | Логировать попытки, исход, ошибки и время последнего успеха; 3 повтора после первичной ошибки | Must |
| SR-06 | Считать длительность после завершения; план <= 0 — ошибка данных | Must |
| SR-07 | Хранить расходы/платежи отдельно и считать бюджетное отклонение по расходам | Must |
| SR-08 | Хранить направление/порог KPI и безопасно обрабатывать нулевой план | Must |
| SR-09 | Подтверждать смену статуса уполномоченным сотрудником; хранить историю | Must |
| SR-10 | Поддерживать назначение, комментарии, устранение и проверку отклонений | Must |
| SR-11 | Хранить документы и аудит действий | Must |
| SR-12 | Проверять роль и scope на каждом защищённом endpoint | Must |
| SR-13 | Формировать сводные отчёты с учётом области доступа | Should |
| SR-14 | Не затирать успешные данные ошибочным/пустым ответом; маркировать stale | Must |
| SR-15 | Обеспечить идемпотентность повторной доставки данных | Must |
| SR-16 | Журналировать изменения статусов, плана, отклонений и действия пользователей | Must |

## Нефункциональные допущения
API — JSON over HTTPS; время в БД — UTC. SLA, RPO/RTO, объём нагрузки, срок хранения аудита, классификация данных и реальная схема авторизации требуют согласования. Секреты не хранятся в репозитории.
