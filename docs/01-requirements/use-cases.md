# Use cases

## UC-01 Импорт проекта
**Акторы:** адаптер Модуля 1, Модуль 2. Получить утверждённый пакет; проверить обязательные поля и версию; создать project_id и mapping внешнего ID; сохранить план, этапы, бюджет и KPI. При конфликте версии или невалидных данных вернуть ошибку без перезаписи утверждённого плана.

## UC-02 Синхронизация факта
Планировщик запускает импорт раз в сутки; адаптер получает данные; система сопоставляет источник и внешний ID, проверяет структуру, единицы и дубликаты, сохраняет факты и пересчитывает отклонения. При первичной ошибке выполняются три повтора. После четырёх неудачных попыток сохраняется последняя успешная версия и источник помечается устаревшим.

## UC-03 Обработка отклонения
Система создаёт отклонение; сотрудник ведомства назначает ответственного; представитель предприятия добавляет пояснение; ответственный отмечает устранение; сотрудник ведомства проверяет и закрывает либо возвращает в работу. История действий сохраняется.

## UC-04 Изменение статуса
Система создаёт предложение; сотрудник ведомства подтверждает или отклоняет. Для SUSPENDED/TERMINATED_EARLY вводятся основание, комментарий и документ. При отсутствии любого поля операция отклоняется. Подтверждение записывается в историю.

## UC-05 Просмотр отчёта
Пользователь запрашивает сводку; система проверяет роль и scope; возвращает только доступные проекты и агрегаты. Прямой запрос чужого проекта не раскрывает его данные.
