# Бизнес-правила
- **B-01:** в мониторинг импортируются только утверждённые проекты.
- **B-02:** новая версия плана утверждается отдельно; утверждённые данные неизменяемы.
- **B-03:** внешний ключ уникален по паре (source_code, external_project_id).
- **B-04:** синхронизация планируется раз в сутки.
- **B-05:** для завершённого этапа D=(T_fact−T_plan)/T_plan×100%; при D>10% создаётся отклонение. T_plan<=0 — ошибка качества данных.
- **B-06:** D_budget=(E_fact−E_plan)/E_plan×100%; при D_budget>10% создаётся отклонение. Расходы и платежи не суммируются.
- **B-07:** HIGHER_IS_BETTER — неблагоприятно падение ниже плана сверх порога; LOWER_IS_BETTER — неблагоприятно превышение плана сверх порога.
- **B-08:** статусы проекта ACTIVE, SUSPENDED, COMPLETED, TERMINATED_EARLY.
- **B-09:** статус меняется только после подтверждения сотрудником ведомства; SUSPENDED/TERMINATED_EARLY требуют основания, комментария и документа.
- **B-10:** отклонение хранит тип, измеренное значение, порог, статус и историю.
- **B-11:** ответственное лицо может отметить RESOLVED; CLOSED устанавливает только ведомство после проверки.
- **B-12:** доступ определяется ролью и областью проектов; предприятие не редактирует план и факт.
- **B-13:** отчёты фильтруются по области доступа.
- **B-14:** изменения и интеграционные попытки журналируются.
- **B-15:** после первичной ошибки выполняются три повтора; старые данные сохраняются и помечаются устаревшими.
- **B-16:** повторная доставка source record не создаёт дубликат.
- **B-17:** расчёты допустимы только при сопоставимых единицах, валюте и периоде.
- **B-18:** при нулевом целевом KPI процент не вычисляется автоматически.
