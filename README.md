# Модуль 2. Система мониторинга исполнения проектов промышленной модернизации

## Назначение
Получает утверждённые плановые данные из Модуля 1, синхронизирует фактические данные внешних систем, контролирует этапы, расходы, платежи и KPI, ведёт отклонения и отчётность. Документация учебная; внешние API и SLA — допущения.

## Структура
```text
docs/
  01-requirements/{business-requirements.md,business-rules.md,use-cases.md,system-requirements.md}
  02-diagrams/{bpmn-process.puml,bpmn-process.svg,sequence-diagram.md}
  03-api/{openapi.yaml,mock-data/{application-payload.json,fns-response.json,scoring-response.json}}
  04-db/{erd.md,schema.sql}
  05-testing/test-cases.md
```

## Реестр проектных решений
| ID | Решение |
|---|---|
| R-01 | Фактические данные поступают автоматически из внешних систем |
| R-02 | Интеграции абстрагированы от конкретных поставщиков |
| R-03 | Синхронизация планируется раз в сутки |
| R-04 | План из Модуля 1, факт из внешних API |
| R-05 | Ролевой доступ и область ответственности |
| R-06 | Представитель предприятия видит свои проекты и отправляет пояснения, но не меняет фактические данные |
| R-07 | Отклонение длительности этапа свыше 10% определяется после завершения |
| R-08 | Ведомство назначает ответственного; предприятие поясняет отклонение; ведомство контролирует устранение |
| R-09 | Ответственный отмечает устранение, сотрудник ведомства проверяет и закрывает |
| R-10 | Бюджетный порог >10% по расходам; порог KPI индивидуальный |
| R-11 | После первичной ошибки — три повтора; прежние данные сохраняются и помечаются устаревшими |
| R-12 | Статусы: ACTIVE, SUSPENDED, COMPLETED, TERMINATED_EARLY |
| R-13 | Система предлагает смену статуса, сотрудник ведомства подтверждает |
| R-14 | Для SUSPENDED/TERMINATED_EARLY обязательны основание, комментарий, документ |
| R-15 | Утверждённый план неизменяем; изменение — новая версия с отдельным утверждением |
| R-16 | Отклонения считаются от последней утверждённой версии плана |
| R-17 | Длительность сравнивается после завершения этапа |
| R-18 | Расходы и платежи хранятся отдельно; бюджетный порог — по расходам |
| R-19 | Для каждого KPI задаётся индивидуальный процентный порог |
| R-20 | Направление KPI: HIGHER_IS_BETTER / LOWER_IS_BETTER |
| R-21 | Внутренний project_id и таблица внешних ID по системам-источникам |

## Допущения
1. Время запуска ежедневной синхронизации и часовой пояс настраиваются позднее.
2. Конкретные внешние API, авторизация, SLA и лимиты не определены.
3. Отклонение срока: (факт длительности − плановая длительность) / плановая длительность × 100%; при нулевом плане — ошибка данных.
4. План и факт бюджета должны иметь одну валюту и сопоставимый период.
5. Для KPI с нулевым планом процент не рассчитывается; требуется ошибка качества данных или отдельное правило.
6. Файл документа хранится во внешнем хранилище; в БД сохраняются метаданные и storage_key.
7. Аутентификация через внешний провайдер — допущение.
8. Три повтора следуют после первичной неудачной попытки; интервалы уточняются.
9. Закрытие отклонения всегда подтверждает сотрудник ведомства.
10. Реальная интеграционная совместимость проверяется после получения контрактов источников.
